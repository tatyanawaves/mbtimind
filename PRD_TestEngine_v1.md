## Problem Statement

HR-директора, школьные психологи и деканаты в Казахстане проводят психометрическое тестирование вручную — бумажные анкеты, подсчёт баллов в Excel, результаты на словах. Это занимает 2-4 часа на группу из 30 человек, результаты теряются, нет возможности проверить достоверность ответов и невозможно отслеживать динамику во времени. Существующие онлайн-платформы (16Personalities, Testometrika) не предоставляют B2B-функционал, не хранят данные в РК и не поддерживают казахский язык.

Без решения этой проблемы организации продолжают использовать ненадёжные ручные методы, теряют данные о сотрудниках/студентах и не могут принимать обоснованные решения о карьерном развитии и профориентации.

---

## Goals

1. **Сократить время проведения группового тестирования в 10x** — с 2-4 часов до 15-20 минут на группу из 30 человек (включая раздачу ссылок, прохождение, получение результатов)

2. **Обеспечить психометрическую валидность результатов** — Cronbach's alpha >= 0.7 по каждой из 4 шкал MBTI, с anti-cheating механизмами, снижающими долю невалидных результатов до <5%

3. **Достичь 500 завершённых тестирований в первый месяц после запуска** — через 5-10 пилотных организаций (2-3 HR, 2-3 университета, 2-3 школы)

4. **Confidence score на каждый результат** — каждый результат сопровождается количественной оценкой достоверности (0-1), чтобы организация могла фильтровать ненадёжные результаты

5. **100% соответствие Закону No. 94-V** — все данные хранятся на территории РК, персональные данные обрабатываются с явного согласия

---

## Non-Goals

1. **Адаптивное тестирование (IRT/CAT)** — требует калиброванного банка вопросов на 500+ наблюдениях. Будет реализовано в v2 после накопления данных. Для MVP используем фиксированную последовательность вопросов.

2. **Game-based assessments** — дорого в разработке ($200K+), не критично для core value proposition. Оставляем на Year 2+.

3. **RIASEC/Holland тестирование** — отдельный тест со своей методологией. Будет добавлен как отдельный модуль в v2. Сейчас фокус на MBTI.

4. **Мультиязычное прохождение теста в рамках одной сессии** — пользователь выбирает язык (RU/KZ) в начале, сменить в процессе нельзя. Упрощает логику валидации.

5. **Офлайн-режим прохождения** — требует сложной синхронизации. В MVP — только онлайн. Офлайн-режим через Flutter планируется на v2.

## User Stories

### Администратор организации (HR-директор / Деканат / Школьный психолог)

**US-1:** Как администратор организации, я хочу создать тестовую сессию для группы сотрудников/студентов, чтобы провести массовое MBTI-тестирование без ручной координации.
- Acceptance: Администратор указывает название сессии, выбирает шаблон теста, задаёт дедлайн. Система генерирует уникальную ссылку-приглашение и QR-код.

**US-2:** Как администратор, я хочу видеть прогресс прохождения тестов в реальном времени, чтобы понимать, сколько человек прошли тест и сколько ещё нет.
- Acceptance: Дашборд показывает: всего приглашённых, начали тест, завершили, abandoned. Обновление каждые 30 секунд.

**US-3:** Как администратор, я хочу получить групповой отчёт по результатам, чтобы увидеть распределение типов в команде/группе и выявить закономерности.
- Acceptance: Отчёт содержит: распределение по 16 типам (bar chart), распределение по 4 шкалам, средний confidence score группы, список участников с низким confidence (<0.5) для возможного ретеста.

**US-4:** Как администратор, я хочу скачать результаты в CSV/Excel, чтобы использовать данные в своих системах (1С, внутренние отчёты).
- Acceptance: Экспорт содержит: ФИО, email, тип MBTI, баллы по каждой шкале (%), confidence score, дату прохождения.

### Тестируемый (сотрудник / студент / школьник)

**US-5:** Как тестируемый, я хочу пройти тест на удобном мне языке (русский или казахский), чтобы точно понимать вопросы.
- Acceptance: Выбор языка на первом экране. Все вопросы, инструкции и результаты на выбранном языке.

**US-6:** Как тестируемый, я хочу видеть прогресс прохождения, чтобы знать, сколько вопросов осталось.
- Acceptance: Прогресс-бар с номером текущего вопроса / общего количества. Оценка оставшегося времени.

**US-7:** Как тестируемый, я хочу получить понятный персональный отчёт по результатам, чтобы узнать свой тип личности и понять, что это значит.
- Acceptance: Страница результата содержит: тип MBTI (4 буквы), визуализацию шкал (% по каждой паре), текстовое описание типа (сильные стороны, зоны роста), рекомендации по профессиям (топ-10).

**US-8:** Как тестируемый, я хочу продолжить прерванный тест с того места, где остановился, чтобы не проходить заново.
- Acceptance: Сессия сохраняется в Redis. При повторном входе (по ссылке или авторизации) тест продолжается с последнего отвеченного вопроса. Сессия живёт 72 часа.

### Системный администратор платформы

**US-9:** Как сис-админ, я хочу видеть алерты о подозрительных сессиях (anti-cheating), чтобы проверять и при необходимости аннулировать результаты.
- Acceptance: Событие TestIntegrityAlert генерируется при: L-scale > 7, скорость ответа < 1.5с на 50%+ вопросов, обнаружении flat/alternating паттерна. Алерт содержит: session_id, тип нарушения, severity (warning/critical).

## Requirements

### Must-Have (P0)

| # | Требование | Acceptance Criteria |
|---|-----------|-------------------|
| P0-1 | **Создание тестовой сессии** — администратор создаёт сессию, получает ссылку-приглашение | Ссылка уникальна, содержит token; QR-код генерируется автоматически; сессия имеет дедлайн |
| P0-2 | **MBTI-опросник (forced-choice)** — 60-70 вопросов с парными утверждениями | Каждый вопрос — выбор между двумя утверждениями (A или B); порядок рандомизирован; все 4 шкалы покрыты равномерно (15-18 вопросов на шкалу) |
| P0-3 | **Scoring engine** — подсчёт типа MBTI по ответам | Для каждой шкалы: % в сторону каждого полюса; тип = 4 буквы (доминирующий полюс каждой шкалы); confidence score по формуле: 0.4 * scale_clarity + 0.3 * timing_consistency + 0.3 * integrity_score |
| P0-4 | **Персональный отчёт** — страница результата для тестируемого | Тип MBTI, визуализация шкал, текстовое описание типа (RU/KZ), топ-10 рекомендованных профессий |
| P0-5 | **Групповой отчёт** — дашборд для администратора | Распределение типов, статистика по шкалам, список участников с результатами, фильтр по confidence score |
| P0-6 | **Anti-cheating (базовый)** — 3 механизма: L-scale, speed detection, flat pattern detection | L-scale: 8-10 контрольных вопросов социальной желательности; Speed: фиксация времени ответа на каждый вопрос; Flat: детекция одинаковых ответов подряд (>10) |
| P0-7 | **Двуязычность (RU/KZ)** — все вопросы, интерфейс и результаты на двух языках | Выбор языка при начале теста; все 60-70 вопросов переведены на оба языка; описания типов на обоих языках |
| P0-8 | **Сохранение сессии** — возможность продолжить прерванный тест | Состояние сессии в Redis (TTL 72ч); восстановление по session_id; прогресс отображается корректно |
| P0-9 | **Row Level Security** — мультитенантная изоляция данных | Каждая организация видит только свои данные; RLS-политики на уровне PostgreSQL; тестируемый видит только свои результаты |
| P0-10 | **Согласие на обработку данных** — GDPR/Закон No. 94-V | Чекбокс согласия перед началом теста; текст политики конфиденциальности; для несовершеннолетних (<18) — согласие от родителя/опекуна |

### Nice-to-Have (P1)

| # | Требование | Acceptance Criteria |
|---|-----------|-------------------|
| P1-1 | **Экспорт в CSV/Excel** — выгрузка результатов | Администратор скачивает файл с результатами группы; формат: ФИО, тип, баллы по шкалам, confidence, дата |
| P1-2 | **Anti-cheating (расширенный)** — alternating pattern, total time, midpoint bias | Alternating: A-B-A-B паттерн; Total time: тест пройден подозрительно быстро (<5 мин); Midpoint: все ответы в середине шкалы |
| P1-3 | **Email-уведомления** — напоминание о незавершённом тесте | Автоматическое email за 24ч до дедлайна для тех, кто не завершил |
| P1-4 | **Повторное прохождение** — возможность пройти тест повторно | Администратор разрешает ретест; система сохраняет историю всех прохождений; сравнение результатов (1-й vs 2-й раз) |
| P1-5 | **Массовое приглашение** — загрузка списка участников из CSV | Администратор загружает CSV (ФИО, email); система отправляет персональные приглашения каждому |

### Future Considerations (P2)

| # | Требование | Rationale |
|---|-----------|-----------|
| P2-1 | **Адаптивное тестирование (CAT/IRT)** | Требует калибровки вопросов на >500 наблюдениях. Сократит количество вопросов с 60-70 до 30-40 |
| P2-2 | **RIASEC/Holland тест** | Отдельный модуль профориентации. Комбинация MBTI + RIASEC для более точных рекомендаций |
| P2-3 | **Офлайн-режим (Flutter)** | Для школ в регионах с нестабильным интернетом. Синхронизация при подключении |
| P2-4 | **API для внешних интеграций** | OpenAPI-совместимый API для подключения к 1С, Workday, SAP SuccessFactors |
| P2-5 | **ML-рекомендации** | Коллаборативная фильтрация на основе накопленных данных (>10K результатов) |

## Timeline Considerations

### Фазы разработки

**Фаза 1 — Core MVP (8 недель)**
- Неделя 1-2: Модель данных, PostgreSQL-схема с RLS, базовый API (FastAPI)
- Неделя 3-4: Scoring engine, anti-cheating (L-scale, speed), банк вопросов (RU)
- Неделя 5-6: Фронтенд прохождения теста (Next.js), персональный отчёт
- Неделя 7-8: Админ-панель: создание сессий, групповой отчёт, дашборд прогресса

**Фаза 2 — Pilot Ready (4 недели)**
- Неделя 9-10: Казахский перевод вопросов и интерфейса, расширенный anti-cheating
- Неделя 11-12: Экспорт CSV/Excel, email-уведомления, нагрузочное тестирование, bugfix

### Зависимости

- **Auth Module** — должен быть готов до начала (регистрация организаций, JWT)
- **User Module** — профили пользователей и привязка к организации
- **Перевод вопросов на казахский** — внешняя зависимость (переводчик + психолог для валидации)
- **KZ дата-центр** — аренда сервера и настройка Docker Compose до начала Фазы 2

### Hard Deadlines

- **Заявка Astana Hub AI-Preneurs:** дедлайн подачи — необходим работающий прототип
- **Пилот в 5 организациях:** целевая дата — 12 недель от старта разработки
